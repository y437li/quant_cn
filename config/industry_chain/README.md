# config/industry_chain/ — the product taxonomy and chain skeleton (plan 12 phase 1, D-097)

Written by Opus as a **prior**: every edge here is `source: prior` (general industry knowledge, no
document evidence). Company → product edges never live here; they come from documents (plan 12 ph4–5).

## Files
- `_common.yaml` — cross-sector nodes: materials, technologies, end markets. Reuse these ids; never redefine.
- `_merged_ids.yaml` — ids removed by the cross-sector merge (`old_id: surviving_id`). Translate any stored id
  through it. Generated by `quant_cn_lake/meta/runs/merge/merge_taxonomy.py`; do not edit by hand.
- `<sw_l1_code>_<slug>.yaml` — one file per Shenwan 2021 L1 sector (31 files).

## Node
```yaml
- id: PROD_ELEC_SIC_SUBSTRATE   # ^(SEG|PROD|MAT|TECH|MKT)_[A-Z0-9]+(_[A-Z0-9]+)*$, globally unique
  type: product                 # segment | product | material | technology | end_market
  name: 碳化硅衬底               # Chinese canonical name, unique within its type
  name_en: SiC Substrate
  parent: PROD_ELEC_SIC          # optional is-a parent, same type (taxonomy tree)
  segment: SEG_ELEC_POWER_SEMI   # products only: the segment it belongs to (required for products)
  kind: product                  # products only: product (physical good) | service (default product)
  import_dependence: high        # optional, products/materials: China's reliance on imports (high | medium | low); prior
  aliases: [SiC衬底, 碳化硅单晶衬底] # optional; Chinese and English variants found in filings/reports
```
Products and services are both `type: product`; services set `kind: service` (IDC operation, cloud, CRO/CDMO,
testing and certification, logistics, EPC contracting, brokerage, lending, game publishing, ...). Revenue
shares and peers are computed over products and services together (D-102).

Granularity: distinguish stages a company can specialise in (SiC powder ≠ crystal ≠ substrate ≠ epitaxy ≠
device ≠ module). A product is something a listed company could report as revenue or capacity.

## Edge (list of [subject, relation, object])
| relation | subject → object | meaning |
|---|---|---|
| `upstream_of` | product/material → product/material | object is made from / one stage after subject (a product stage may make a commodity: naphtha → ethylene) |
| `component_of` | product → product | subject is a physical part of object |
| `uses_material` | product → material | object is a key raw material of subject |
| `used_in` | product → product / end_market | subject is deployed in object |
| `enables` | technology → product | technology is required to make the product |
| `substitute_for` | product/material → product/material | competing alternative for the same function (either direction, e.g. granular silicon ↔ polysilicon) |
| `operates` | product → product | a service runs an asset (airline passenger transport operates aircraft) |
| `part_of` | segment → segment | sub-segment |
| `serves` | segment → end_market | segment sells into end market |

## Ownership and cross-sector rules
Every concept is defined once, in the file of the Shenwan L1 whose listed companies mainly make it; other sectors
link to it by id. Names and aliases are unique per node type across all files; an alias that means two things
is made specific (e.g. `TPU芯片` vs `TPU弹性体`). A product may reference a segment or parent in another file.
Edges live in the subject's file (the object's file when the subject is a `_common.yaml` node).

## sw_l3_map
Every Shenwan L3 code of the sector → one or more segment ids (the segments its members operate in).
